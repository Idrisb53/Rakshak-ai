# Contributing

Thanks for helping improve Rakshak AI.

## Before opening a pull request

1. Describe the problem and the proposed change.
2. Keep changes focused and document any behavior change.
3. Never commit secrets, `.env` files, private keys, customer data, or real malicious samples.
4. Do not claim that a security check is operational unless it is implemented and tested.
5. Run the available checks:

   ```bash
   bun run lint
   bun run build
   ```

6. Include safe reproduction steps and tests where practical.

## Reporting bugs

Include the route, expected behavior, actual behavior, and minimal reproduction steps. Redact account details, tokens, and personal information.
